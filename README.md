# Сервер картинок

Сервис для загрузки изображений и получения прямых ссылок на них. Техническое задание находится в [project_description.md](project_description.md), план работ — в [project_plan.md](project_plan.md).

> В ТЗ для обработки HTTP-запросов в качестве примера указана стандартная библиотека (`http.server`). Backend реализован на FastAPI: он даёт асинхронную обработку параллельных запросов, встроенный разбор multipart-форм и автоматическую документацию API (`/docs`).

## Стек и архитектура

- Python 3.12+, FastAPI и Uvicorn — HTTP API и HTML-страницы.
- Pillow — проверка фактического формата изображения.
- Nginx — прямая раздача загруженных файлов из общего тома `images` и статики из `static/`; остальные запросы проксируются в FastAPI.
- Docker Compose — отдельные сервисы `app` и `nginx`, именованные volumes `images` и `logs`.
- Интерфейс сверстан по макету Figma и HTML-шаблону из ТЗ на чистых HTML и CSS, без JavaScript: страницы в `templates/`, стили и картинки в `static/`.

## Адреса и маршруты

| Метод и маршрут | Обработчик | Назначение |
|---|---|---|
| `GET /` | FastAPI | Главная страница: приветствие, описание сервиса, ссылки на загрузку и каталог. |
| `GET /upload` | FastAPI | Страница загрузки: форма выбора файла, поле со ссылкой на последнюю загрузку. |
| `POST /upload` | FastAPI | Загрузка изображения (описание ниже). |
| `GET /images/` | FastAPI | Каталог загруженных изображений: имя, прямая ссылка, кнопка удаления. |
| `GET /images/<имя_файла>` | Nginx | Прямая ссылка на изображение для просмотра и скачивания. |
| `POST /delete/<имя_файла>` | FastAPI | Удаление изображения из каталога. |
| `GET /static/...` | Nginx | CSS и картинки интерфейса. |
| `GET /health` | FastAPI | Проверка состояния backend: `{"status": "ok"}`. |
| `GET /docs` | FastAPI | Автоматическая документация API (Swagger UI). |

Пользовательский адрес — `http://localhost:8080` (Nginx), backend напрямую — `http://localhost:8000`. Ссылки на изображения всегда ведут на Nginx; адрес задаётся переменной окружения `PUBLIC_BASE_URL` в `compose.yaml`.

### `POST /upload`

Принимает multipart-поле `file`. Поддерживаются JPG, PNG и GIF до 5 МБ (5 МиБ) включительно; Pillow проверяет, что содержимое действительно является изображением и соответствует расширению. Файл сохраняется в `/images` под уникальным именем `<uuid>.<расширение>`.

Форма на странице `/upload` отправляет файл этим запросом, и браузер получает ту же страницу со ссылкой на изображение или с сообщением об ошибке. Остальным клиентам, например `curl`, сервер отвечает JSON:

```bash
curl -F "file=@photo.png" http://localhost:8080/upload
```

```json
{"id": "6deacbfdd83f461fb00d8a84b45fc4d0", "url": "/images/6deacbfdd83f461fb00d8a84b45fc4d0.png", "full_url": "http://localhost:8080/images/6deacbfdd83f461fb00d8a84b45fc4d0.png"}
```

При ошибке возвращается HTTP 400 с причиной: `{"detail": "Поддерживаются только форматы JPG, PNG и GIF"}`. Браузер отличается по заголовку `Accept: text/html`.

### `POST /delete/<имя_файла>`

Отправляется кнопкой удаления в каталоге. Удаляет изображение, загруженное сервисом: имя должно иметь вид `<32 hex-символа>.jpg|png|gif`. После удаления браузер перенаправляется обратно в каталог (303). Ошибки: 400 — некорректное имя, 404 — файл не найден. Как и ссылки на изображения, удаление не требует авторизации — её нет в ТЗ.

## Логирование

Действия пользователей пишутся в `app.log` в формате `[Дата/время] Действие: сообщение`:

```text
[2026-10-15 17:01:26] Просмотр: открыта главная страница.
[2026-10-15 17:01:26] Просмотр: открыт каталог изображений (2 шт.).
[2026-10-15 16:54:07] Успех: изображение 6deacbfdd83f461fb00d8a84b45fc4d0.png загружено.
[2026-10-15 17:01:26] Ошибка: Поддерживаются только форматы JPG, PNG и GIF (notes.txt).
[2026-10-15 17:01:26] Ошибка: маршрут не найден (GET /nope).
```

Логируются просмотры страниц, успешные загрузки, все отклонённые загрузки с причиной, удаления изображений, а также запросы к несуществующим маршрутам и неподдерживаемым методам. Отдачу самих изображений выполняет Nginx, поэтому она попадает в его access-лог (`docker compose logs nginx`), а не в `app.log`.

Случайное UUID-имя затрудняет угадывание ссылки, но не является авторизацией: любой, у кого есть ссылка, может открыть изображение.

## Запуск локально

Требуются Python 3.12+ и pip.

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установка зависимостей и запуск:

```bash
python -m pip install -r requirements.txt
uvicorn app:app --reload --host 127.0.0.1 --port 8000
```

Локально файлы и логи сохраняются в `images/` и `logs/` рядом с приложением.

## Запуск в Docker

Установите Docker Desktop и выполните из корня проекта:

```bash
docker compose up --build
```

Откройте `http://localhost:8080/`. Для остановки нажмите Ctrl+C; чтобы остановить фоновые контейнеры, используйте `docker compose down`. Данные в именованных volumes сохраняются между перезапусками.

- backend: `http://localhost:8000`
- Nginx и пользовательские маршруты: `http://localhost:8080`
- лог приложения: `/logs/app.log` внутри контейнера `app`

## Тесты

Тесты не используют реальные каталоги приложения или Docker volumes:

```bash
python -m unittest
```

## Структура проекта

```text
.
├── app.py              # FastAPI-приложение: маршруты, проверка, сохранение, логирование

├── compose.yaml        # сервисы app и nginx, порты, volumes images и logs

├── templates/          # HTML-страницы: index.html, upload.html, images.html
├── static/
│   ├── css/            # reset.css и style.css по HTML-шаблону
│   └── img/            # иконки и картинки главной страницы
├── tests/              # автоматические тесты backend
├── images/             # локальный каталог изображений (в Docker — volume images)
└── logs/               # локальный каталог логов (в Docker — volume logs)
```
