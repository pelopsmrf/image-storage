# План разработки проекта «Сервер картинок»

## Контекст

Цель — создать сервис хранения изображений, который легко запускать, тестировать и демонстрировать. В ТЗ для HTTP-обработки в качестве примера предлагается стандартная библиотека; backend реализован на FastAPI ради асинхронной обработки запросов, разбора multipart-форм и автодокументации API.

## Архитектура

- FastAPI обрабатывает запросы и HTML-страницы; Uvicorn обслуживает приложение на порту 8000.
- Nginx слушает порт 8080, проксирует backend-маршруты и раздаёт сами изображения из общего read-only volume.
- FastAPI сохраняет картинки в `/images`, логи — в `/logs/app.log`; Docker Compose подключает именованные volumes `images` и `logs`.
- Поддерживаемые форматы: `.jpg`, `.png`, `.gif`; Pillow сверяет заявленное расширение с фактическим содержимым; максимум 5 МиБ на файл.
- Каждому файлу присваивается случайное UUID-имя. Ссылка доступна всем, кто её знает; аутентификация не входит в ТЗ.

## Этапы и контрольные точки

1. **Каркас проекта.** Настроить Python 3.12+, FastAPI/Uvicorn, Dockerfile, Compose и Nginx. Проверить, что схема сервиса и порты соответствуют требованиям.
2. **Backend.** Реализовать `GET /`, `GET /upload`, `POST /upload`, `GET /images/`, `GET /health`; валидировать, сохранять и логировать загрузки. Контрольная точка: локально загрузить допустимое изображение и получить ссылку; показать ошибки для неверного файла.
3. **Тесты.** Проверить успешные форматы, проверку содержимого, лимит, отсутствие файла, уникальные имена, каталог и логи с временными каталогами. Запускать через `python -m unittest`.
4. **Nginx.** Точный location `= /images/` направляет HTML-каталог в backend; location `/images/` раздаёт отдельные файлы из volume с выключенным autoindex. Остальные запросы проксируются на `app:8000`.
5. **Docker Compose.** Сохранить сервисы `app` и `nginx`, порты 8000/8080, именованные volumes `images`/`logs`, multi-stage build и запуск backend не от root. Проверить `docker compose config`, затем запуск, маршруты и сохранность volumes.
6. **Приёмка.** Обновить README, запустить тесты и пройти демонстрационный сценарий: загрузить каждый формат, открыть прямую ссылку, показать ошибки и лог, перезапустить Compose и подтвердить сохранность данных.

## Сценарии проверки

- Открыть главную и форму через Nginx на `http://localhost:8080`.
- Загрузить JPEG, PNG, GIF; проверить JSON с UUID и прямой ссылкой.
- Проверить HTTP 400 для пустого запроса, неподдерживаемого расширения, несоответствия расширения содержимому, повреждённого изображения и файла больше 5 МиБ.
- Проверить каталог `/images/`, прямую раздачу файла Nginx и 404 для несуществующего файла.
- Убедиться, что в `/logs/app.log` есть записи успеха/ошибки и что volumes переживают пересоздание контейнеров.
